# Rem v0.1 MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.1 of Rem: an offline Android reminder app with natural-language quick add, one-time and recurring reminders, multiple alerts per reminder, snooze, notification actions, lists, Today/Upcoming/Overdue views, alarm-style full-screen reminders with a repeating "nag" mode, and reminders that survive a reboot. It uses no AI APIs and no server.

**Architecture:** Two Gradle modules. `:core` is pure Kotlin/JVM with no Android dependencies. It holds the domain model, the RRULE recurrence engine, the rule-based quick-add parser and the alarm planner, so the logic can be tested anywhere with plain JUnit. `:app` is the Android shell: Room persistence, an `AlarmManager` scheduler, broadcast receivers, notifications, a full-screen alarm activity and the Compose UI. It calls `:core` for every decision about *when* something fires.

**Tech Stack:** Kotlin 2.1.0 · Gradle 8.14 (wrapper) · AGP 8.7.3 · Jetpack Compose (BOM 2024.12.01) + Material 3 · Room 2.6.1 · Hilt 2.53.1 · KSP 2.1.0-1.0.29 · JUnit 5.11.4 (core) · JUnit 4 + Robolectric 4.14 (app) · `java.time` only for dates (no date libraries).

**Spec:** `docs/PRODUCT_SPEC.md` (sections "Core principle: no AI APIs", "Core reminders (MVP)", "Data model", "Roadmap → v0.1")

## Global Constraints

- No AI/LLM APIs and no network calls in v0.1. The manifest must not declare `INTERNET`.
- `minSdk 26`, `targetSdk 35`, `compileSdk 35`, JVM target 17.
- `:core` must not depend on any Android or AndroidX artifact. It uses only the Kotlin stdlib and `java.time`.
- `settings.gradle.kts` includes `:app` only when an Android SDK is found (`ANDROID_HOME`, `ANDROID_SDK_ROOT`, or `sdk.dir` in `local.properties`), so `./gradlew :core:test` works on machines without the SDK.
- Times are stored as a wall-clock `LocalDateTime` plus an optional `zoneId` (`null` means "follow the device zone"). Instants are computed only when scheduling.
- Recurrence is stored as an RFC 5545 RRULE string (subset below).
- Package root: `app.rem`. Application ID: `app.rem`.
- Notification channels: `reminders` (default importance) and `alarms` (high importance, alarm sound, bypasses DND only if the user allows it).
- Snooze presets, exactly: 5 min, 15 min, 1 h, "Tonight" = today 20:00 (or tomorrow 20:00 if already past), "Tomorrow morning" = tomorrow 09:00.
- Default nag interval: 5 minutes. Nagging stops at Done, Dismiss, Snooze, or after 12 repeats.

## Review Focus

1. **DST jumps:** a 02:30 daily reminder on a spring-forward day fires at 03:30 that day and at 02:30 the next day. An autumn-back 01:30 fires once, not twice. → Task 4 test `dstGapShiftsForwardAndOverlapFiresOnce`.
2. **"At 9am" typed after 9am:** a quick add with a time but no date that is already past today means tomorrow, not a reminder that is instantly overdue. → Task 3 test `pastTimeWithoutDateRollsToTomorrow`.
3. **Month-end recurrence:** "every month on the 31st" skips months without a 31st (RFC behaviour). "Last day of month" (`BYMONTHDAY=-1`) hits Feb 28/29. → Task 2 tests `monthDay31SkipsShortMonths`, `lastDayOfMonthHitsFebruary`.
4. **Device clock or zone changes and exact-alarm permission revoked:** all alarms are rescheduled on `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED` and `MY_PACKAGE_REPLACED`. If `canScheduleExactAlarms()` is false, fall back to `setAndAllowWhileIdle` and surface a warning banner. → Task 6 tests `rescheduleAllOnTimeChange`, `fallsBackToInexactWhenExactDenied`.
5. **Completing a recurring reminder:** Done advances to the next occurrence (from the scheduled time, not "now", so a late completion doesn't drift). A recurrence that has hit its COUNT/UNTIL becomes DONE. → Task 4 test `completeRecurringAdvancesFromScheduledTime`, `completeFinalOccurrenceMarksDone`.

### Task 2: Recurrence engine (RRULE subset)

**Files:**
- Create: `core/src/main/kotlin/app/rem/core/recurrence/RecurrenceRule.kt`
- Test: `core/src/test/kotlin/app/rem/core/recurrence/RecurrenceRuleTest.kt`

**Interfaces:**
- Produces:
  ```kotlin
  enum class Freq { DAILY, WEEKLY, MONTHLY, YEARLY }
  data class WeekdayNum(val day: DayOfWeek, val ordinal: Int? = null) // ordinal: 1..5 or -1..-5
  data class RecurrenceRule(
      val freq: Freq, val interval: Int = 1,
      val byDay: List<WeekdayNum> = emptyList(),
      val byMonthDay: List<Int> = emptyList(),     // 1..31 or -1..-31
      val byMonth: List<Int> = emptyList(),
      val count: Int? = null, val until: LocalDateTime? = null,
  ) {
      fun toRRule(): String                         // canonical, e.g. "FREQ=WEEKLY;INTERVAL=2;BYDAY=MO,WE"
      /** Next occurrence strictly after [after]; [start] is the series anchor (DTSTART). */
      fun next(start: LocalDateTime, after: LocalDateTime, occurrencesSoFar: Int = 0): LocalDateTime?
      companion object { fun parse(rrule: String): RecurrenceRule }  // throws IllegalArgumentException
  }
  ```
  Occurrences keep the time-of-day of `start`. Without BYDAY/BYMONTHDAY, WEEKLY uses `start`'s weekday, MONTHLY uses `start`'s day of month, and YEARLY uses `start`'s month and day. A monthly anchor on day 31 skips months that don't have it.

  - `weeklyMonWedFri`: start Mon 2026-11-23T07:00, after Mon 07:00 → Wed 2026-11-25T07:00. After Fri 2026-11-27T07:00 → Mon 2026-11-30T07:00.

  ```kotlin
  data class ParsedReminder(

  )
  ```
